Notes for every reader of these sets:

- **The nodes' VIP cells never leave the node.** k8s-cp2, the nodes' client, is a node of the cluster, and Cilium, which replaces kube-proxy, translates a Gateway's VIP to a Gateway pod at connect(): the connect to either VIP succeeds and no line for its source port is in the firewall's traffic log (M/verdict.txt:48 to :62), while the operator's allowed requests to the same VIP are logged as allowed (M/fw/traffic-log-443.txt:154 to :156, and the entries at :158, :162, :166). So the nodes' Users' Gateway cell is allowed, and `nodes-to-internal-gateway` (L/fw/running-security-policy.txt:363) is on the path of no matrix cell. A tcpdump on k8s-cp2 during the attempt before this recording saw no packet to 10.20.11.210 while the connect succeeded; that check is not in any set.
- **"Silent" at the uplink router.** The two storage data cells the uplink router refuses (operator, internet host) end at the client with `ERROR:Network_unreachable` within about 1 ms, not a timeout (M/requests/operator-stor-data-connect-a1.txt:1, web-stor-data-connect-a1.txt:1, M/verdict.txt:42, :88): a router on the path answered with an unreachable, which no set captured. "Silent" in the matrix means no rule logged the request and nothing of the platform answered; the chapter should not say the client saw nothing. MATRIX.md:70 says each silence's evidence is "a capture at the hop"; no capture is in the set: the evidence is the route table, the drop counter and the absent log line in each cell's row.
- **Both Gateway VIPs on one node.** k8s-ingress2 held both leases (A/verdict.txt:694, :697; T/cluster/lease.txt:2).
- **containerlab's version check.** The deploy ran with the version check disabled, and containerlab printed `Failed fetching latest version information` (N/rec-make-up.txt:225) in place of a release notice.
- **The refusals' client view.** Every refused cell the firewall logs timed out at the client's 4 s connect timeout (`TIMEOUT 4.004`, M/requests/enterprise-node-connect-a1.txt:1); the trace's refused SSH connect uses the walk's own 5 s timeout (T/verdict.txt:72).
- **The key refusal's message.** The API gateway answers any key the route does not admit with `{"message":"Authorization Failed"}` (M/requests/enterprise-chat-other-a1-body.txt:1); revision 1's `Invalid API key in request` is gone.
- **The label summary.** L's and RL's `LABELS.md` list the Caller row's batch and helpdesk groups but not staff's, and cite the placement rows without a line number, because of two faults in `label.py`'s summary writer found after the recording and fixed in the commit that adds these sets; the verdicts are complete. For staff's group quote L/key/api-gateway-routes.yaml:144, :145 (its desc) and :154 to :159 (its consumer, `staff_ent_client`, an `oidc-consumer` with subject `ent-client@tarnwick.example`), and L/verdict.txt:77, :78; for the placement rows L/placement/serving.env:31 to :41.
